# Contorro codebase audit — 2026-07-08

Deep-dive audit of CMS ↔ Studio ↔ design-system integration. Five parallel audit passes (Payload layer, Studio↔CMS data flow, admin composition flow end-to-end, architecture, design-system pipeline), all findings verified in working-tree code. Typecheck passes; every "broken" item below is behavioral.

**Verdict:** the owner's assessment is substantiated. The bones are right (Components / PageCompositions / Pages with drafts, Studio-authored JSON trees, whole-document saves), but the system is broken in four load-bearing places, carries an entire dead hexagonal vertical (30 workspace packages for one Next.js/Payload app + one React editor), and re-implements Payload features (field UI, validation, versioning, locking, media resolution) instead of using them.

---

## 1. Broken product flows (CRITICAL)

### 1.1 Anonymous visitors 404 on template-based pages
`apps/cms/src/app/(frontend)/[slug]/page.tsx:181-208` fetches pages with `overrideAccess: false` (outside draft mode) and `depth: 1`, but `page-compositions.access.read = authenticatedAccess` (`packages/infrastructure/payload-config/src/collections/PageCompositions.ts:28`). Population of the `pageComposition` relationship is denied for anonymous users → relationship stays an ID → `notFound()` for template-only pages; pages with template + blocks silently drop the template section. The blocks path only works anonymously because `render-designer-content.tsx:133` uses default `overrideAccess: true` — an accidental asymmetry.
**Fix:** public read access scoped to `{ _status: { equals: "published" } }` on `page-compositions` (and `components`), or fetch composition explicitly with `overrideAccess: true` + published constraint.

### 1.2 Library-component instances silently vanish from published pages
Two independent causes, same symptom — the ref fails to expand and the **live site** renders the grey `PrimitiveEmptyState` debug placeholder (`packages/runtime/primitives/src/library-component.tsx:9-30`):

- **Styled instance:** `graftEmbeddedAtRef` (`packages/domains/composition/src/graph/expand-library-component-nodes.ts:93-131`) deletes the ref node but never prunes its style binding → orphaned binding → `validatePageCompositionInvariants` fails → expansion skipped (`:161-165`). Studio explicitly allows styling `primitive.libraryComponent` nodes (`style-authoring.ts:384`). Any margin/width on a placed instance kills it in production while canvas looks fine.
- **Same component placed twice:** `clonePageCompositionWithNewIds` (`graph/clone-composition.ts:37-46`) preserves `contentBinding.editorField.name`; every `primitive.button` is auto-bound at creation (`graph/mutations.ts:151-161`), so two instances carry identical field names → `validateEditorFieldNamesUnique` fails inside graft → second instance skipped.

**Fix:** prune/transfer ref style bindings during graft; namespace editor-field names per instance (e.g. prefix with ref id); log every skipped ref; render `null` (not debug placeholder) in production.

### 1.3 Render-time editor-field merge destroys authored content
`mergeEditorFieldValuesIntoComposition` (`packages/domains/composition/src/editor-field-values.ts:126-164`) rewrites `propValues` for **every** node with `contentBinding.source === "editor"` using `cmsValue ?? spec.defaultValue` — it never falls back to the node's current `propValues`. Consequences (each verified):

- **Empty content:** field absent from `templateEditorFields` → text patched to `""` (`:87`), image `src: ""` (`:91`). In `[slug]/page.tsx:111-125` this merge runs over the **entire expanded tree** whenever any template CMS value is filled → embedded library-block instance values are wiped. The repo's own seed (`seed-page-with-library-template`) hits this.
- **Stale text:** text `defaultValue` is captured once at expose time (`property-inspector-primitive-inspectors.tsx:160-166`) and never re-synced; later canvas edits render as the old text (or empty) in production while canvas shows the new text.
- **Buttons force-rewritten:** the button case (`editor-field-values.ts:106-116`) forces `linkType: "url"` and blanks `collectionSlug`/`entrySlug`. All buttons are auto-bound, so one filled CMS field rewrites every button on the page from stale defaults — a `payloadCollection`-linked button becomes a dead `href: ""` link.

**Fix (structural):** merge only when a CMS value actually exists (`raw !== undefined`); fallback chain `value ?? node.propValues ?? defaultValue`; scope template-value merge to pre-expansion template-owned nodes; make button/text CMS exposure opt-in, not auto-bound.

### 1.4 Design-system publish is a no-op (variable namespace mismatch)
Token compiler emits `--color-primary`, `--radius-base`, `--typography-font-sans` (`packages/config/tailwind/src/compiler.ts:132-134`). But `apps/cms/src/app/theme.css` uses `@theme inline`, so Tailwind bakes `var(--primary)`, `var(--radius)`, `var(--font-sans)` into every built utility. **No bridge exists between the two namespaces** — publishing tokens never rethemes the site or the shadcn chrome the Studio design-system editor claims to control. Typography and Radius tabs are 100% dead ends (the inspector never offers those token categories either — `property-inspector-style-model.ts:333-378` returns false for text section, radius not in size categories).
**Fix:** compile tokens to the shadcn base names (`color.primary` → `--primary`) or drop `inline` from `@theme`. One mapping decision.

### 1.5 Token sets freeze after first publish
"Keys immutable after publish" is implemented as byte-identical key-set equality (`packages/domains/design-system/src/aggregates/design-token-set.ts:53-72`) — blocks **additions**, on every save including drafts. The editor's own `setTokenValue` appends rows for new key/mode combos (e.g. touching any color in dark mode) → 400 → swallowed as generic "Save failed. Try again."
**Fix:** reject only removed/renamed previously-published keys (`prevKeys ⊆ nextKeys`), publish-time only; surface API error in editor.

### 1.6 Blocks silently deleted on page save / template switch
Pages `beforeValidate` rewrites `contentSlots` to exactly the template's slot order; `mergePageContentSlotsToSlotOrder` (`packages/domains/composition/src/page-content-slots.ts:55-58`) drops blocks in any slot not in the order; every fallback path (relationship read failure, Zod fail) collapses to `["main"]`. Template switch in admin resets the form immediately (`PageContentSlotsField.tsx:204,225`) — blocks in removed regions vanish pre-save, no warning.
**Fix:** reassign orphaned blocks to default slot or block the change with confirm; never fall back to `["main"]` when the template exists but couldn't be read.

### 1.7 Admin-UI create of Components / Page templates always 400s
Both collections show create buttons (`componentAuthoringAccess`/`composerAuthoringAccess`) but required canonical fields are hidden JSON only Studio populates → `beforeValidate` throws on any admin-UI create.
**Fix:** hide create in admin UI for these collections, or default the composition on create.

### 1.8 Draft saves of Pages blocked by required-field validation
`page-and-component-validation.ts:143-192,254-260` throws for missing required block fields on **draft** saves too — re-implements Payload validation without Payload's skip-on-draft semantics. Editors can't save work in progress.
**Fix:** enforce required values on publish only.

## 3. Data-loss races (HIGH)

1. **Check-then-act concurrency:** `saveCompositionCommand` (`packages/application/studio/src/commands/save-composition.ts:38-49`) does `loadRevision` → compare `ifMatchUpdatedAt` → `save` as three separate calls, no transaction. Two designers in the race window both pass; last write wins silently. Push the predicate into the write (`where: { updatedAt: { equals } }`) or use a version column.
2. **Rename clobbers concurrent save:** `renamePageCompositionTitle` (`payload-studio-mutation-repository.ts:95-113`) re-writes `composition: existing.composition ?? default` from a stale read with **no** if-match. Rename should update title only.
3. **Dirty-flag clobber:** `studio-store.ts:284-303` sets `dirty: false` unconditionally after save response, wiping edits made during the in-flight request → unsaved-changes guard lets user navigate away → keystrokes lost. Recompute dirtiness post-save.
4. **Racy uniqueness loop:** `ensureUniqueComponentKey` runs up to 64 sequential `find`s with no `req` (outside transaction) — classic TOCTOU; concurrent "Hero" creates → opaque 500. Hooks generally omit `req` on nested Local API calls (`component-key-from-title.ts:21-41`, `page-and-component-validation.ts` — also N+1 `findByID` per block per save).
5. **Selection mutates document:** button inspector effects call `setNodeEditorFieldBinding` on mount/sync (`property-inspector-primitive-inspectors.tsx:822-883`) — selecting a node dirties a clean doc and destroys redo history.

## 4. Over-engineering / dead code (architecture)

Fallow static analysis + per-symbol grep verification. 0 circular deps. 12.06% duplicated lines (5,372/44,541). ~80% of LOC is real product logic — the problem is topology: 30 packages, 4 in-process layers, second HTTP app defending a save path that is `route → payload.update`.

### Dead verticals (zero production callers, all verified)

The 3 live commands add trim/validate and forward. ## 5. Design-system pipeline (beyond §1.4/1.5)

- **CSS explosion, measured:** `compileTokenSet` emits every token × 47 properties × 5 breakpoint variants = **8,225 rules / 779 KB** for the default 35-key set — including nonsense like `.display-color-primary { display: var(--color-primary) }`. Served `no-store` per request AND embedded in every studio composition GET/POST/PATCH response. On top of that, a **4,850-class build-time safelist** (`_tailwind-safelist-composition-generated.css`, 46 KB of names) generates the utility space a second way, shipped to public visitors.
- **Canvas color mode wrong:** canvas token variables follow the editor chrome theme (localStorage), not `DesignSystemSettings.activeColorMode` — which is read nowhere. WYSIWYG wrong in both directions.
- **Silent drops:** renderer skips token bindings not in the active set (`style-resolver.ts:41-43`) — switching default token set blanks styles with no warning. Dark-only tokens compute invalid in light mode (`:root { --x: var(--x--light, var(--x--dark)) }` with `--x--dark` only defined inside `.dark`).
- **12 token categories in schema, ~3 usable end-to-end;** studio filter references category strings the Zod enum can't produce (two hand-maintained lists, drifted). Brand scoping (`activeBrandKey`/`scopeKey`) is write-only fiction; fallback set selection is `find({ limit: 1 })` with no sort — arbitrary with multiple sets.
- **Target shape:** tokens compile to one small `:root`/`.dark` variable block (~5 KB) using the same names the built Tailwind theme references; cache keyed on `updatedAt`, tag-revalidate on publish; consume via `var(--token)` only; delete both class-generation mechanisms.

## 6. What's done right (keep)

- Studio API routes: textbook `payload.auth({ headers })` → role check → Local API with `user` + `overrideAccess: false`.
- RBAC via `saveToJWT` role; drafts on Pages/Components/PageCompositions; unique+indexed slugs; `filterOptions: { _status: published }` on block picker.
- `push: false` + committed migrations + generated schema.
- Core tree mutations correct (moveNode cycle check, removeSubtree binding pruning, id remapping); no-autosave + beforeunload guard is a sane design; 409 conflict UX exists.
- Client-side node editing in the store with domain mutation functions — the right call; the dead server-side command mirror is the mistake, not this.

## 7. Target architecture & refactor sequence

**Core inversion to undo:** stop storing admin-editable content in `json` blobs with hand-rolled UI, stop merging values into the whole tree at render time, and stop maintaining infrastructure for features that don't exist.

The one honest constraint: block types are user-authored at runtime, so Payload's static `blocks` field can't model them without a config-regeneration step. Two viable shapes:
- **(a) Keep dynamic (smaller step):** keep `contentSlots[].blocks[]` but make values structured — generate per-component field groups (or at minimum `jsonSchema`-validated json) from the component's editor-field manifest; merge values per-instance only where a CMS value exists.
- **(b) Payload-native blocks (bigger step):** generate real block configs from published component manifests (text→text, image→upload, button→group + hidden componentKey), regenerated on component publish (requires config reload/redeploy step). Deletes `EditorFieldsInputs.tsx` + all four custom Field components + both form-state resolvers + server value-validation hooks; Payload provides field UI, required/draft semantics, media picking, versions, autosave, localization natively.

**Sequence (fix-broken first, then collapse):**
1. **Ship-stoppers (days):** public read access on page-compositions/components (§1.1); prune ref style bindings + namespace per-instance field names in graft (§1.2); merge fallback `value ?? propValues ?? defaultValue` + stop blanking button link fields (§1.3); token variable namespace bridge (§1.4); relax token key-freeze to subset check (§1.5); production seed guard + kill default password (§2).
2. **Data-safety (days):** atomic if-match save; title-only rename; dirty-flag recompute; draft-skip required validation; preserve orphaned slot blocks; thread `req` through hook operations.
3. **Deletion pass (low-risk, high-leverage):** dead verticals, gateway, empty shells, my-route, duplicate migrate in check script, dedupe shadcn via one ui package or accept cms copy from studio package.
4. **Consolidation:** 30→7 packages; inline live commands into cms; Zod on the wire for the 4 composition payloads; adopt generated payload-types.
5. **Content-model decision:** pick (a) or (b) above; add `admin.livePreview` + authenticated preview enter/exit; `versions.maxPerDoc`; cache compiled token CSS.

Estimated deletion: roughly a third of audited code with zero feature loss, before the content-model refactor.
